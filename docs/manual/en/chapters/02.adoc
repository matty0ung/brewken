== Chapter 2: General Concepts

Chapter 1 showed how to put a recipe together.  This chapter explains how {app-name} organises what you put into it --
where things are stored, what is shared between recipes and what isn't, and how to keep track of your stock -- and how
to get recipes in and out of the program.

=== The Database

Everything {app-name} knows -- recipes, ingredients, profiles, brew logs, inventory -- is kept in a single database.  By
default this is an SQLite file called `database.sqlite`.  To see where it is, or move it, go to the *Databases* tab of
menu:Edit[Options] and look at *Data Directory*.

==== Backups

{app-name} makes automatic backups of the database file when you close it: by default, every fourth time, keeping the
last ten.  You can change this on the *Databases* tab: *Frequency of Backups* is how many times the program has to be
closed for another backup (1 means every time), and *Number of Backups* is how many to keep (0 means don't make any,
and -1 means never delete old ones).  The backups go in the *Backup Directory*.

To make a backup by hand, use menu:File[Database > Backup].  menu:File[Database > Restore] replaces your current
database with a backup, so everything you have changed since that backup is lost.  You need to restart {app-name}
afterwards.

==== PostgreSQL

If you want to share one set of recipes between several computers, or simply prefer a database server, you can use
PostgreSQL instead of SQLite.  On the *Databases* tab, set *RDBMS Engine* to PostgreSQL, fill in the connection details,
and click btn:[Test Connection].  When you save, {app-name} offers to copy your existing data into the new database, and
then needs restarting.

The automatic and manual backups described above only work for SQLite.  For PostgreSQL, use the database's own backup
tools.

==== New Default Content

Each release of {app-name} comes with a set of ingredients, styles, profiles and example recipes.  When a new release
adds to these, it asks whether you want them added to your database.  Saying yes doesn't change or remove anything you
already have.

=== Ingredients, Recipes and What Is Shared

Fermentables, hops, miscellaneous ingredients, yeasts, styles, equipment and water profiles are each stored once, and
recipes refer to them.  So when you add Maris Otter to a recipe, the recipe doesn't get its own copy of Maris Otter: it
gets an *addition* of it.  The addition holds what is specific to the recipe -- the amount, and when it goes in -- while
everything else (yield, colour, alpha acid and so on) belongs to the ingredient.

This has two consequences:

* If you change an ingredient, the change applies to every recipe that uses it.  To keep the old figures for older
  recipes, select the ingredient in the tree and use menu:Edit[Copy Selected Item(s)], then change the copy and use that
  instead.  (You will be asked for a name for the copy.)
* You can't delete an ingredient that a recipe uses.  {app-name} tells you how many recipes are using it.

The same goes for styles and equipment.  Their editors show which recipes use them.

If you end up with several identical entries for the same ingredient -- eg after importing recipes from different
places -- select them in the tree, right-click and choose *Merge selected*.  This makes every recipe use one of them and
removes the others.  It can't be undone, so make a backup first.

==== Mash, Boil and Fermentation Profiles

Mash, boil and fermentation profiles are also stored once and can be shared between recipes, as many brewers use the
same mash or fermentation schedule for several recipes.  A new recipe gets a boil and a fermentation profile of its own,
and you choose a mash profile for it (see Chapter 1).  When you copy a recipe, the copy shares the original's profiles.

The line next to the drop-down on the Mash, Boil and Fermentation tabs tells you how many recipes use the profile.  If
you want to change a profile for one recipe without affecting the others, open it in its editor and click
btn:[Make a copy for this recipe].

A profile can also be *locked*, so that it can't be changed by accident.  The example profiles supplied with
{app-name} are locked, so that they stay available for any recipe.  You can still use a locked profile in a recipe, or
copy it, and you can lock or unlock your own profiles with the btn:[Lock] and btn:[Unlock…] buttons in the editors.

Features that change a profile automatically -- eg keeping a mash in sync with the recipe -- only work on a profile that
just one recipe uses, as otherwise changing one recipe would silently change the others.

==== Locked Recipes

Ticking *Recipe Locked* on the Recipe tab stops the recipe's style, equipment, batch size and efficiency from being
changed, and stops the recipe from being deleted.  Its mash, boil and fermentation profiles can't be changed either,
even if other recipes share them.

=== Trees and Folders

Each tree on the left of the main window can hold folders, and folders can hold other folders.  Right-click in a tree
for a menu of what you can do there:

* menu:New[Folder] makes a new folder.  You can also create a new item of whatever is in that tree.
* *Rename* and *Delete* work on folders as well as on items.  Deleting a folder deletes everything in it, after asking
  you to confirm.
* *Copy* makes a copy of the selected items (the same as menu:Edit[Copy Selected Item(s)]).
* *Export* and *Import* are described under <<Importing and Exporting>> below.  Importing from the right-click menu on a
  folder puts what you import in that folder.

To move things between folders, drag them.  You can select several items with kbd:[Ctrl] or kbd:[Shift] as usual.

=== Brew Logs

Each time you brew a recipe (see Chapter 1), {app-name} creates a brew log, which appears under the recipe in the
recipe tree.  Right-click a brew log for these options:

* *Brew again* makes a new brew log for today, copied from the selected one, and takes the ingredients out of your
  inventory again.  This is quicker than Brew It! when you brew the same recipe the same way.
* *Change date* changes the date of the brew log.
* *Delete* deletes the brew log.

=== Snapshots

Once you have brewed a recipe, its brew logs only make sense if you know what the recipe was on the day.  If you then
change the recipe -- eg to tweak the hops for next time -- you would lose that.  *Snapshots* solve this.

Snapshots are off by default.  To turn them on, go to the *Recipe Snapshots* tab of menu:Edit[Options] and tick *Enable
Automatic Snapshots*.  Then, the first time you change a recipe after brewing it, {app-name} first takes a snapshot of
the recipe as it was, and moves the brew logs to the snapshot.  The recipe you are editing then carries on as before.
Snapshots are locked, so that they stay as they were brewed.

image::screenshots/recipeTree.png["The recipe tree, showing a snapshot of a recipe with its brew log",pdfwidth=40%]

Snapshots are hidden in the tree unless you choose to see them: right-click a recipe and choose
menu:Snapshots[Show Snapshots], or tick *Show snapshots by default* in the options.  The same menu also has:

* *Snapshot Recipe*, to take a snapshot yourself, whether or not you have brewed the recipe;
* *Detach Recipe*, to separate a recipe from its most recent snapshot, which then becomes a recipe in its own right
  (with any older snapshots still attached to it).

You can also link existing recipes together, with one as a snapshot of another, using menu:Tools[Ancestors].

The *Deleting a recipe* option, on the same tab of the options, says whether deleting a recipe also deletes its
snapshots.

=== Inventory

{app-name} can keep track of your stock of ingredients, so that you know what you have, what you need to buy, and what
needs using up.  You don't have to use this: if you never enter any stock, nothing else is affected.

Stock is recorded as *stock purchases*.  Each purchase is of one ingredient, and has the amount, the dates it was
ordered and received, a best-before date, the supplier, the price and so on.  (Most of these are optional.)  To add a
purchase, right-click the ingredient in its tree and choose menu:New[Stock Purchase], or use the inventory window,
menu:View[Inventory].

image::screenshots/stockWindow.png["The Inventory window",pdfwidth=100%]

When you click Brew It!, {app-name} takes the ingredients the recipe uses out of your stock, starting with the purchase
that is due to be used first -- by best-before date if there is one, otherwise by the date it was received, otherwise
by the date it was ordered.  Each time stock is taken from a purchase, this is recorded against the purchase as a *use*,
along with the brew log it was for.  The uses are listed in the purchase's editor, where you can also add your own,
eg for spillage or for stock you throw away.

The *Total Inventory* column in the ingredient tables shows how much of each ingredient you have left.

Stock measured by weight can't be used for an addition measured by volume, or vice versa, as {app-name} has no way to
convert between them.  If this means Brew It! can't take everything it needs from stock, it tells you.

=== Units and Precision

As described in Chapter 1, you can choose the units {app-name} shows on the *Units & Precision* tab of
menu:Edit[Options], or for one field by right-clicking its label.  The right-click menu also lets you choose the
*Scale* (eg grams or kilograms) and the number of *Decimal Places* for that field.

Everything is stored in metric units, whatever you choose to see, so changing units never changes any of your data.

=== Undo and Redo

menu:Edit[Undo] and menu:Edit[Redo] cover changes you make in the main window, for as long as {app-name} is running.
Changes made in an editor (eg the hop editor) are kept only when you click btn:[Save] in the editor.

=== Importing and Exporting

{app-name} can read and write three file formats:

dotBeer (`.beer`)::
{app-name}'s own format, which holds everything {app-name} knows about a recipe or an ingredient.  Use this to move
things between copies of {app-name}.  (Brewken and Brewtarget both use it, so you can also use it to move things
between the two.)

BeerJSON (`.json`)::
A newer standard format, supported by a growing number of brewing programs.

BeerXML (`.xml`)::
The older standard, supported by most brewing programs.  It can't hold some of what {app-name} records -- eg boil and
fermentation profiles -- so only use it for programs that don't read the other two.

To import, use menu:File[Import from File], or right-click a folder in a tree and choose *Import* to import into that
folder.  If something in the file is the same as something already in your database, {app-name} uses what you already
have rather than importing it again.  If something has the same name as something you already have but is different,
it is imported with a number added to its name -- eg "Oatmeal Stout (1)".

To export, select what you want in a tree (recipes, ingredients, profiles or folders), and either use
menu:File[Export to File] or right-click and choose *Export*.  Exporting a recipe also exports everything it uses.

=== Sharing and Printing a Recipe

menu:Edit[Recipe to Clipboard as Text] copies the current recipe as plain text, ready to paste into an email or a forum
post.

menu:File[Print and preview] prints the recipe, the brew day instructions or your inventory, or saves them as a PDF or
HTML file.
